# 안건 검토용 프롬프트

다른 AI 도구에 그대로 붙여 넣어도 쓸 수 있도록 정리한 요청 틀이다. 긴 프롬프트를 외울 필요는 없고 아래 여섯 요소만 있으면 된다.

## 좋은 요청의 여섯 요소

| 요소 | 이사회 준비에 적용 |
|---|---|
| 역할 | 사외이사의 검토 보조자 |
| 목적 | 회의에서 물을 질문 준비 |
| 자료 | 안건, 수치표, 전략 요약 |
| 기준 | 사실, 가정, 누락과 반론 |
| 형식 | 쟁점, 근거, 질문, 요청자료 |
| 한계 표시 | 불명확하면 "확인 필요" |

"너는 사외이사야"처럼 역할만 주는 요청으로는 부족하다. AI의 답은 넣어 준 자료의 품질과 범위를 넘지 못한다.

## 공통 프롬프트

`[ ]` 부분만 본인 전문분야로 바꿔 쓴다.

```text
너는 사외이사의 이사회 준비를 돕는 검토 보조자다.
제공한 안건·수치표·회사 전략을 바탕으로 작성하라.
1. 의결사항·금액·일정·책임자를 정리하라.
2. 문서상 사실·성과 가정·미기재를 구분하라.
3. 수치 불일치와 근거 부족을 찾아 쪽수·문구를 제시하라.
4. 내 전문 분야 [재무/준법/리스크/IT]의 질문 5개를 제시하라.
5. 반론과 이를 해소할 증빙, 추가 요청자료 3개를 정리하라.
출력: 쟁점 / 근거 위치 / 확인 질문 / 요청자료 / 중요도.
자료에 없으면 '확인 필요'로 표시하고 미기재를 미실시로 단정하지 마라.
회사 전략이나 규정 원문이 없으면 적합성을 확정하지 마라.
최종 찬반 대신 판단에 필요한 근거를 정리하라.
```

마지막 세 줄이 AI의 과도한 단정을 막는다.

## 막연한 요청과 검토를 돕는 요청

| 구분 | 요청 | 문제 또는 효과 |
|---|---|---|
| 막연한 요청 | "이 안건 괜찮나요? 승인해도 될까요?" | 범위, 기준, 출력 형식이 없다 |
| 검토를 돕는 요청 | "사실, 가정, 미기재를 구분하고, 근거 위치와 함께 질문 5개, 추가 요청자료 3개를 제시하세요." | 확인할 내용과 자료가 연결된다 |

마지막에 꼭 붙일 한 줄: **"자료에 없으면 추정하지 말고 확인 필요로 표시하세요."**

## 단계별 요청

| 단계 | 요청 | 얻는 것 |
|---|---|---|
| 1단계(질문) | "이 안건을 요약해 주세요." | 목적, 주요 수치, 일정, 낯선 용어 |
| 2단계(생산) | "이 안건을 이사회 검토 메모로 정리해 주세요. 항목은 의결사항, 쟁점, 근거가 있는 쪽수, 확인할 질문, 추가 요청자료로 나눠 주세요." | 쟁점, 근거 위치, 확인 질문, 추가 자료 |

요약 다음에 바로 "승인해도 되나요?"를 묻지 말고 사실과 가정을 나누고 질문과 요청자료를 붙이게 한다.
