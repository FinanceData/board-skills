# 이사회 안건 검토 메모

사외이사는 짧은 기간에 제한된 안건 정보만 가지고 판단한다. 이 스킬의 목표는 안건을 더 빨리 읽는 것이 아니라 **근거가 연결된 질문**을 준비하는 것이다. 결과물은 검토 메모 1장, 우선 질문 5개, 추가 요청자료 3개다.

## 지켜야 할 원칙

1. **최종 찬반을 내지 않는다.** "승인해도 됩니다/안 됩니다"가 아니라 판단에 필요한 근거를 정리한다.
2. **모든 쟁점에 근거 위치(쪽수, 원문 문구)를 붙인다.** 자료에 없으면 추정하지 않고 `확인 필요`로 표시한다.
3. **미기재를 미실시로 단정하지 않는다.** "안건에서 중단 기준을 확인할 수 없습니다"는 되지만 "위험관리를 하지 않았습니다"는 안 된다. 회사가 검토하고도 안건에 넣지 않았을 수 있으므로 질문은 "검토하셨습니까?"로 쓴다.
4. **기대치를 실현치처럼 쓰지 않는다.** 연간 기대 총편익은 달성된 금액이 아니다. "손익 기여"와 "투자금 전액 회수"도 다른 개념이다.
5. **회사 전략이나 규정 원문이 없으면 적합성을 확정하지 않는다.** 규정 검토는 `board-compliance-check`로 넘긴다.
6. **사용자가 결론을 내비쳐도 맞장구치지 않는다.** "좋아 보이는데 맞죠?"에는 "이 사업에 반대하는 이사라면 무엇을 묻겠습니까?"로 바꿔 답한다.

## 진행 순서

### 0. 입력 전 확인
실제 비공개 안건이 오면 먼저 한 줄로 확인한다. 이 대화가 회사가 허용한 서비스·계정인지, 고객 실명이나 식별 가능한 정보가 들어 있지 않은지. 불확실하면 `board-ai-safety-check`를 먼저 돌리고, 확인이 끝나기 전에는 가상 자료나 숫자·이름을 뺀 구조만으로 진행한다.

### 1. 자료와 전문분야 확인
받은 자료(안건 본문, 수치표, 전략 요약)와 사용자의 전문분야(재무·회계 / 법률·준법 / 리스크 / IT·보안)를 확인한다. 전략 요약이 없으면 "전략과의 적합성은 판정하지 못한다"고 처음에 밝힌다.

### 2. 의결 요청 정리
의결사항, 금액, 일정, 책임자와 보고체계를 표로 정리한다. 안건에 없는 항목은 칸을 비우지 말고 `미기재`로 적는다.

### 3. 사실·가정·미기재 분류
안건의 주요 문장을 세 가지로 나눈다. 여기서 "사실"은 현실의 진위가 아니라 **제공 문서에 적힌 내용**이라는 뜻이다.

| 분류 | 예 | 이유 |
|---|---|---|
| 문서상 사실 | 승인 요청액은 150억 원이다 | 안건에 명시된 요청 내용 |
| 성과 가정 | 연간 총편익 45억 원을 기대한다 | 숫자는 있으나 미래의 기대치 |
| 미기재 | 사업을 중단할 손실 기준 | 안건에서 찾을 수 없음 |

### 4. 수치 대조
세부 항목은 직접 더해 요청액과 맞는지 본다. 합계가 다르면 원인(계산 오류, 중복, 별도 예산)을 단정하지 말고 "요청액과 세부 내역을 맞춘 조정표"를 요청하는 질문으로 만든다. 계산은 `board-number-check`의 스크립트를 쓴다. 암산으로 합계를 내지 않는다.

### 5. 전략 연결
회사 전략, 안건에 적힌 것, 추가로 물을 것을 3열 표로 놓는다. 지표가 있어도 그것이 전략 목표(예: 소기업 고객 거래 확대)와 같은 것인지 따로 확인한다. 마무리 질문으로 목표 달성 지표, 기준 시점, 측정 책임자를 묻는다.

### 6. 우선 질문 5개
의결에 바로 영향을 주는 것부터 고른다. 기본 순서는 아래와 같고, 안건에 따라 바꿔도 된다. 위원회나 보고체계는 회사마다 다르므로 임의로 가정하지 않는다.

1. 승인 범위: 요청액과 세부 합계의 차이는 무엇인가
2. 편익 근거: 총편익의 산식, 중복, 실현 시점은 어떻게 검증했는가
3. 대안 비교: 단계 도입, 외부 제휴, 현상 유지와 무엇을 비교했는가
4. 위험·중단: 성과 미달이나 사고 시 축소·중단 기준은 무엇인가
5. 책임·보고: 누가 어떤 지표로 사후 성과와 위험을 보고하는가

질문은 넓게 묻지 않고 **확인할 주장 + 판단 기준 + 필요한 증빙**으로 쓴다. 예: "사업성이 있습니까?" 대신 "편익 실현율 60%에서도 손익 기여 목표를 달성합니까? 연도별 현금흐름을 제시해 주세요." 추가 예시는 `references/pitfalls.md`.

### 7. 추가 요청자료 3개
자료를 많이 요청하는 것이 목표가 아니다. 각 자료가 **어떤 질문에 답하는지** 번호로 짝지어 쓴다. 3개 묶음을 기본으로 한다.

1. 예산 조정표와 연도별 현금흐름 → 질문 1, 2
2. 대안 비교와 편익 검증 자료 → 질문 2, 3
3. 위험·준법·운영 검토와 책임체계 → 질문 4, 5

### 8. 자체 점검과 AI 지적 검증
내놓기 전에 질문마다 확인한다.
- 근거: 원문 위치나 수치가 있는가
- 구분: 사실, 가정, 미기재가 나뉘어 있는가
- 행동: 질문과 요청자료가 연결되어 있는가

내가 만든 지적도 검증 대상이다. "문제"라고 쓴 문장마다 원문에서 해당 문구를 다시 찾고, 근거 위치를 대지 못하면 표현을 낮추거나 뺀다.

## 출력 형식

기본 표는 `쟁점 / 근거 위치 / 확인 질문 / 요청자료 / 중요도` 다섯 열이다. 메모 전체 틀은 `references/review-memo-template.md`를 쓴다. 마지막에는 항상 `확인 필요`와 한계(받지 못한 자료, 확정하지 못한 항목)를 따로 적는다. 질문의 책임은 이사에게 있으므로 "초안이며 원문 대조와 중요도 판단은 이사가 한다"고 밝힌다.
