# 규정 검토: AI의 몫과 사람의 몫

규정 검토는 **원문 → 적용 → 대조 → 확인**의 절차를 남긴다. AI는 앞의 두 단계와 질문 정리를 돕고, 적용 여부와 위반 판단은 준법·법률 담당의 몫이다.

이 스킬은 절차를 안내하며 특정 법률의 해석을 제공하지 않는다. 법률 자문이 아니다.

## 지켜야 할 원칙

1. **위반 여부, 적합 여부를 확정하지 않는다.** "위반입니다/적법합니다"라고 쓰지 않는다. 규정 원문과 실제 사실관계가 모두 없으면 법규 적합성을 확정할 수 없다.
2. **기억에서 조문을 인용하지 않는다.** 조문 번호와 문구는 공식 원문을 열어 확인한 것만 쓴다. 확인하지 못했으면 "확인하지 못함"이라고 쓴다.
3. **원문을 찾았다는 것과 그 원문이 주장을 뒷받침한다는 것은 다르다.** 링크나 조문을 제시할 때는 해당 문장이 실제로 그 문서에 있는지 열어서 확인하고, 사용자에게도 링크를 열어 확인하라고 안내한다.
4. 문서의 **성격을 구분**한다. 법령, 감독규정, 지침, 모범사례는 구속력과 요구사항이 다르다. 어느 것인지 밝힌다.
5. 안건에 없는 것은 **미기재**이지 미실시가 아니다.
6. 규정 사례를 다룰 때는 **그날 기준 공식 원문**을 먼저 확인한다. 개정·시행일이 다를 수 있다.

## 절차

| 단계 | 내용 |
|---|---|
| 원문 | 발표기관·문서명, 해당 부분을 찾는다 |
| 적용 | 적용 대상, 시행일, 조건을 확인한다 |
| 대조 | 안건의 관련 사실과 나란히 놓는다 |
| 확인 | 준법·법률 검토 근거를 담당자에게 요청한다 |

### 역할 분담

| AI에 요청할 것 | 담당자에게 확인할 것 |
|---|---|
| 관련 공식 원문과 해당 부분 찾기 | 적용 여부와 검토 의견 |
| 불명확한 사실과 확인 질문 정리 | 실제 조치, 증빙, 미해결 사항 |
| 법령, 감독규정, 지침, 모범사례 구분 | 각 문서의 성격과 요구사항 |

## 진행

1. 안건에서 규정과 관련될 만한 사실을 뽑는다(고객 보호, 정보 보호, 외부 위탁, 이해상충, 보고·공시 등). 쪽수를 붙인다.
2. 웹 검색이나 법령 조회 도구(예: `korean-law-search` 스킬이 설치되어 있으면)로 공식 원문을 찾는다. 도구가 없으면 사용자에게 원문을 붙여 달라고 요청한다. 찾은 것마다 아래 형식으로 적는다.

   | 문서 | 발표기관 | 성격(법령/감독규정/지침/모범사례) | 시행일·개정일 | 관련 부분 | 원문 링크 | 열어서 확인함 |
   |---|---|---|---|---|---|---|

3. 안건의 사실과 원문 요구사항을 나란히 놓고 **일치/불일치/확인 불가**가 아니라 "확인이 필요한 지점"으로 정리한다.
4. 담당자에게 물을 질문과 요청자료로 바꾼다. 예:
   - "이 사업에 적용되는 규정은 무엇이며 적용 시점은 언제입니까?"
   - "준법 검토 의견서와 미해결 사항을 제시해 주십시오."
   - "고객 설명 방식과 피해 대응·보상 책임은 어떻게 정해져 있습니까?"
5. 마지막에 확인하지 못한 것(찾지 못한 원문, 확인하지 못한 개정 여부, 받지 못한 사실관계)을 따로 적는다.
