# 안건 숫자 점검

LLM은 암산하다 틀릴 수 있다. 같은 AI라도 계산 도구를 쓰게 하면 정확도가 달라진다. 이 스킬은 합계와 회수기간을 **스크립트로** 계산하고, 결과를 안건의 문구와 나란히 놓아 질문으로 바꾼다.

## 원칙

- 합계, 비율, 회수기간은 직접 계산하지 말고 `scripts/check_numbers.py`를 실행해 나온 값을 쓴다.
- 차이가 나와도 **원인을 단정하지 않는다.** 계산 오류, 중복 항목, 별도 예산, 부가세·예비비 포함 범위 중 무엇인지는 자료만으로 알 수 없다. 질문은 "왜 틀렸습니까?"가 아니라 "승인 요청액과 세부 내역을 맞춘 조정표를 주십시오"로 쓴다.
- 회수기간은 **단순 민감도 예시**다. 할인, 세금, 편익이 늘어나는 과정, 투자 지출 시점을 반영하지 않는다. NPV나 경제성 승인의 근거로 쓰지 않고, 이 계산만으로 사업성이 없다고 결론짓지 않는다.
- 편익은 경영진의 기대치다. 실현율을 바꿔 보는 것은 "가정이 빗나가면 결과가 얼마나 달라지는가"를 묻기 위해서다.
- 표나 도표를 이미지에서 읽은 숫자는 원본과 대조한다. 확인할 것은 축과 단위(억 원과 백만 원), 실적과 전망의 구분, 합계와 원문의 일치, 읽기 어려운 부분을 추정했는지다.

## 사용법

Python 3만 있으면 된다(외부 패키지 없음). 이 스킬 폴더 기준 경로이므로 실행 위치에 맞게 경로를 조정한다.

### 세부 예산 합계 대조

```bash
python scripts/check_numbers.py sum --requested 150 개발=90 시스템연계=35 인프라=25 교육전환=15
```

종료 코드는 일치하면 0, 불일치하면 1이다. 이 사례는 합계 165억 원으로 요청액 150억 원과 15억 원 차이가 난다.

### 단순 회수기간과 실현율 민감도

```bash
python scripts/check_numbers.py payback --investment 150 --benefit 45 --opex 12 --build-months 18
python scripts/check_numbers.py payback --investment 150 --benefit 45 --opex 12 --realization 60
```

- `--realization`은 `0.6`과 `60` 모두 받는다. 기본값은 100%다.
- 기본 출력에 실현율 100·80·60·40% 민감도 표가 붙는다. 끄려면 `--no-sensitivity`.
- 순편익이 0 이하이면 "회수가 성립하지 않음"으로 출력한다.

## 결과를 해석하는 순서

1. 계산에 쓴 입력값과 그 출처(안건 몇 쪽)를 먼저 적는다.
2. 스크립트 결과를 그대로 옮긴다.
3. 안건의 기대치와 어떻게 다른지 한 문장으로 쓴다. 예: "경영진 가정이 40% 빗나가면 출시 후 회수기간이 4.55년에서 10년으로 늘어납니다."
4. 이어서 물을 질문으로 바꾼다. 예: "편익 45억 원의 산식과 연도별 실현 시점, 실현율 60% 시나리오의 현금흐름을 제시해 주십시오."
5. 세부 예산 합계가 요청액과 다르면 회수기간 계산 전에 그 차이를 먼저 조정해야 한다고 덧붙인다.

기준이 되는 계산 예시는 `references/worked-example.md`에 있다. 스크립트 출력이 이 값과 다르면 입력이 잘못된 것이다.
